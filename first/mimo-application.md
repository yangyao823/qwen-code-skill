# MiMo 百万亿 Token 激励者计划 — 申请文案

## 项目名称

**Qwen Code 可视化工作流编排器：长链推理驱动的 Agent 协同编程工具**

## 项目简介

我们为 Qwen Code（阿里开源终端 AI Agent）开发了一个可视化工作流编排 Skill。用户通过拖拽节点、连线、一键执行的方式，将多步骤的 AI 编程任务组织为可复用的工作流。支持文件操作、Shell 执行、AI 代码分析、HTTP 请求、条件判断、延时等待六种节点类型，执行时按拓扑序自动调度，实时反馈每个节点的运行状态。

## 为什么需要大量 Token

AI 编程的本质是**反复迭代**。一个典型的工作流场景：

1. AI 读取项目代码（消耗输入 Token）
2. AI 分析代码问题并生成修改建议（消耗输出 Token）
3. 执行 Shell 命令验证修改（消耗上下文 Token）
4. 根据结果调整方案，重新分析（**再次消耗 Token**）
5. 循环 3-5 轮直到通过测试

单次迭代的 Token 消耗约 2000-5000，一个完整工作流往往需要 5-10 个节点串联执行，涉及数十轮 AI 推理。**长链推理**意味着每一步都依赖前一步的输出，上下文窗口不断累积，Token 消耗呈线性甚至超线性增长。

在实际开发中，一个中等复杂度的代码重构任务（如"将 Express 迁移到 Fastify"）可能触发 20+ 次 AI 调用，总 Token 消耗轻松突破 10 万。批量测试多个工作流方案时，Token 需求量更大。

## Agent 协同价值

本项目的独特之处在于将**多个 AI Agent 的能力编排为可组合的工作流**。每个节点可以是独立的 Agent 调用，节点之间通过数据流连接，形成 Agent 协同链。这种模式让 Qwen Code 从"单次对话"升级为"持续自动化"，是 Token 高效利用的关键路径。

## 申请理由

- 项目面向 Qwen Code 生态，与 MiMo 平台高度契合
- 工作流场景天然产生大量 Token 调用需求
- 长链推理 + Agent 协同是 Token 消耗的核心场景
- 项目已开源，具备社区推广价值
